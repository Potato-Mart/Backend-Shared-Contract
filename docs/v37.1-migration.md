# v37.1 migration

Pin `github.com/Potato-Mart/Backend-Shared-Contract/v37 v37.1.0` in services
that consume the new courier request-configuration models. The Go module path
remains `/v37`; this additive release requires no database migration.

## Courier request configurations

`DeliveryAPIRequestConfigurations` has optional `connection`, `shipping_areas`,
and `time_slots` requests. An absent purpose or field group is unconfigured;
the contract does not seed endpoint paths or field values.

Each `DeliveryAPIRequestConfiguration` carries a `GET` or `POST` method, an
`endpoint_path` relative to the existing
`DeliveryProviderCredentials.api_base_url`, and optional `headers`, `query`, and
`json_body` arrays. Header and query values are JSON strings. JSON-body values
are JSON values assembled as a top-level object; body keys must be unique.

Each `DeliveryAPIRequestField` contains a key and exactly one of:

- `value`: a non-secret, non-null JSON value. Header/query values must be strings.
- `value_is_null: true`: an explicit JSON null for a JSON-body field. It is not
  valid for header or query fields.
- `secret_ref`: the name of a key in the separately protected
  `provider_extension.values` credential set. The secret itself is not part of
  request configuration.

Supply validates field exclusivity and content, resolves secret references,
stores credentials securely, and executes the requests. Supply's update and
test/invoke DTOs, credential-presence projection, request overrides, HTTP
status, and raw JSON result remain service-owned. Older courier models,
including inert `custom_metadata`, keep their existing meanings.
